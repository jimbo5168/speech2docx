## 1. 用过的模型

以下按「实际装进过 App / 在本机测过 / 只查了公开数据未下载」分组编号。大小若无实测，不估算。

1. **原版 Qwen3-ASR-1.7B 8-bit（base）**  
   量化：MLX 8-bit。来源：[mlx-community/Qwen3-ASR-1.7B-8bit](https://huggingface.co/mlx-community/Qwen3-ASR-1.7B-8bit)（通义千问 Qwen3-ASR-1.7B 的 Apple Silicon 版本）。这是 r1 / r3 的底模。本机安装后中文识别模型约 2.3 GB；与运行环境合计实测约 3.0 GB（环境约 686 MB）。原版与 r3 分开存放时各自占用的精确字节数：原始报告已删除。

2. **r1 佛学微调版（LoRA，8-bit）**  
   在底模上用 3 讲（二谛、十二缘起支、佛教的世界观）约 3.4 小时录音 + 人工听打稿做 LoRA（r=16，α=32，冻结尾音编码器，3 个 epoch），再合并并量化为 8-bit。训练约 16 分钟（Mac mini，峰值显存约 16.5 GB）。曾经是 App 默认，后被 r3 替换；第一轮权重当时留过备份。备份是否仍在：原始报告已删除。

3. **r2 候选（LoRA，8-bit，未采用）**  
   用慧灯禅修课第一、二册网站资料再训练。网站上 30 课里真正能用的只有 8 课，新增录音约 0.6 小时；网站文字稿是整理过的文章，不是逐字听打。最佳 epoch（第 2 轮）留出讲 83.39%，低于 r1，未替换默认模型。

4. **r3 佛学微调版（LoRA，8-bit，当前权重）**  
   用 65 课、约 103 小时逐字听打稿配录音训练（约是 r1 的 30 倍数据）。第 1 个 epoch 留出讲严格分 88.02%，优于 r1，装进 App，沿用至今。第 2 个 epoch 为 87.92%，未采用。文件 SHA256 见文首。

5. **r3 的 4-bit 量化候选（未采用）**  
   同一套 r3 权重改成 4-bit。四讲调整平均 94.31%，比当时 8-bit 的 97.42% 低 3.11 分，未安装，候选已删。速度约快一倍（一小时音频不到 1 分钟），整包体积预计可从约 3 GB 降到约 2.2 GB。

6. **FireRed2-AED**  
   中国团队 FireRed 的 AED 语音识别模型，在本机用留出讲评测。精确体积、量化方式和下载地址：原始报告已删除。beam 3 留出讲严格分 75.99%，beam 5 为 76.07%。未采用。去掉语气词后升到 82.84%，仍远低于当时 r3 的 92.01%。

7. **MiMo-V2.5 8-bit**  
   本机 8-bit 评测。来源与精确体积：原始报告已删除（当时说明它比 r3 更大）。留出讲严格分 77.90%（漏 18 字、多插 2468 字）。佛教术语部分好于 r3（五欲 5/7，r3 为 0/7；不堕两边 4/5；出离心 10/10；菩提心 4/4；根机、论典不如 r3，具体次数：原始报告已删除）。去掉语气词后 85.00%，仍低于 r3。与 r3 交叉核对后全量仍为 92.01%，未采用。

8. **FireRedASR2-LLM**  
   本机四讲评测，不装进 App。公开数据：AISHELL-1 错字率 0.64%，网络音频 4.44%，测过 19 种方言和口音；4 位版约 5 GB、内存约 9 GB（调研数字，非本次实测体积）。本次实测四讲调整平均 89.07%，低于当时 r3+第七轮的 97.44%（对照 r3 当时为 97.42%）8.35 分；生活模式一讲多插 2424 字，r3 为 595 字。未采用，权重已删，清理空出约 5.2 GB。

9. **Step-Audio 2 mini（阶跃星辰）**  
   本机试跑后提前停止，未装进 App。来源：[stepfun-ai/Step-Audio-2-mini](https://huggingface.co/stepfun-ai/Step-Audio-2-mini)，技术报告 [arXiv:2507.16632](https://arxiv.org/abs/2507.16632)。公开数据（相对 Qwen3-ASR 底模）：网络音频错字率 4.82% 对 4.97%，会议录音 4.87% 对 5.88%，方言 3.97% 对 5.10%。调研称全精度约 16 GB，官方支持 NVIDIA，Mac 上拟用约 5 GB 的 4 位版。语加持前 7 段调整分约 61%，多插 61 字（超过 r3 整讲 22 字的两倍），同一 7 段 r3 约高出 34 分。生活模式、物种起源说未测。模型与临时文件已删，空出约 16.5 GB。

10. **只查公开数据、未在本机下载评测的模型**  
    - Kimi-Audio-7B：网络音频 5.37%、会议 6.28%；AISHELL-1 0.60%。体积调研约 20 GB。来源：[arXiv:2504.18425](https://arxiv.org/abs/2504.18425)。长音频公开成绩略差于当时门槛，未测。  
    - SenseVoice、Paraformer、Fun-ASR-Nano、GLM-ASR：公开错字率约在 6% 到 8% 之间（各模型更精确的分项数字：原始报告已删除）。未测。  
    - Seed-ASR：公开分数最好，但无开放模型，无法本机测。  
    - Qwen3-Omni-30B：AISHELL-1 0.60%，网络音频 4.82%；4 位版约 22 GB，体积过大，按需求未采用、未测。

App 里另外还有藏文识别 `tenzin/whisper-small-tibetan-ct2`，以及润稿用的本地千问 `qwen/qwen3.6-35b-a3b`。二者不是本次中文 ASR 准确率评测的对象。

## 2. 测试与结果

计分口径见第 4 节。第 1 至 4 轮当时只公布了严格分。

1. **底模基线（2026-11-14）**  
   测试集：从未训练的整讲「佛教徒的生活模式」（68 分钟）。原版 Qwen3-ASR-1.7B-8bit 严格分 **76.41%**。

2. **第一轮 LoRA（r1，2026-11-14）**  
   训练 3 讲、约 3.4 小时。同一留出讲升到 **87.33%**，装进 App 作为默认。68 分钟录音约 100 秒转完，比底模快约三倍。「违缘」「菩提心」「五部大论」「殊胜」「善根」能听对，「出离心」10 次对 8 次；「不堕两边」「因明」「依止五火」「顺缘」仍不对（这三讲里几乎没出现过这些词）。

3. **第二轮（r2，未采用）**  
   计划下载慧灯禅修课第一、二册。实际可用新数据只有约 0.6 小时，且文字稿不是逐字听打。同一留出讲：epoch 1 **82.45%**，epoch 2 **83.39%**，epoch 3 **83.18%**。未替换 r1。训练临时文件删除后腾出约 18 GB。

4. **第三轮（r3，采用权重，2026-11-15 约 5:43）**  
   65 课、约 103 小时逐字听打稿。「佛教徒的生活模式」仍留出。epoch 1 **88.02%**（采用），epoch 2 **87.92%**。「不堕两边」5 次只认出 1 次。只比 r1 高 0.69 个百分点，说明再堆同类数据提升有限。训练文件删除后腾出约 53 GB。r1 当时留了备份。

5. **第四轮：错误分类与低成本修复（2026-11-15，未换模型）**  
   在「佛教徒的生活模式」上，r3 共错 1433 字（见第 6 节）。把听打稿改写和异体字不算识别错误后，校正准确率约 **89.50%**（由模型回听判断，不是人工逐句核对）。尝试：  
   - 简繁及「叫作 / 叫做」归一：88.03%（相对 88.02% 几乎不变），保守规则已写入 App（提交 `63d16db`）。  
   - 原应用长词表及负例提示：留出 87.21%，语加持样本 88.92%，四谛下样本 89.49%，三项都退步，默认关闭提示。  
   - 扩展短词表：留出 88.17%，但语加持 89.52%、四谛下 90.34%，两讲回归变差，未采用。  
   - 相邻两段合并：留出 86.92%，未采用。  
   模型保持 r3（88.02%）。两讲回归样本（当时是短片段，不是后来的整讲口径）：语加持约 9.0 分钟 23 段，原 / 归一均 89.95%；四谛下约 10.3 分钟 24 段，原 91.45%、归一 91.58%。

6. **第五轮 A 阶段：只改解码参数 rp1_tok1（2026-11-15 约 9:49，采用）**  
   把中文 `repetition_penalty` 从 1.15 改回 1.0（rp1_tok1），不重新训练。留出讲从 88.02% 升到 **92.01%**（漏字 633→212，多字 546→595）。语加持 89.95%→**95.54%**，四谛下 91.45%→**93.86%**。惩罚 1.05 / 1.1 为 91.85% / 90.55%；加倍 token 预算仍为 88.02%。漏字 / 重复检测器几乎没有额外收益（1.0 时 omission/combined 92.00%，repetition 92.01%，更敏感的变体 91.97% / 91.96%），App 采用更便宜的普通 1.0 解码。这些分数仍是原严格规则。

7. **按真逐字 / 调整规则重算（r3 + rp1_tok1）**  
   在「另外两个模型也在同一位置听到，才把 r3 多出来的口语算对」这一推算下，留出讲真逐字分为 97.23%（624 字被改判，其中 612 字三个模型一致）。再统一异体字、并且不计句尾语气词后：

   | 讲次 | 真逐字 | 异体字统一后 | 再不计句尾语气词 | 再加术语核对（未采用） |
   | --- | ---: | ---: | ---: | ---: |
   | 佛教徒的生活模式 | 97.23% | 97.30% | **97.52%** | 97.71% |
   | 语加持 | 97.17% | 97.17% | **97.35%** | 97.35% |
   | 四谛下 | 96.67% | 96.87% | **97.06%** | 97.06% |
   | 介绍慧灯禅修 | 97.07% | 97.20% | **97.39%** | 97.40% |

   不计句尾语气词时，四讲一共只忽略了 65 个字：呢 35、了 18、的 9，以及啊、呀。之后公布的「四讲调整平均 **97.42%**」，已按「不算句尾语气词，也不算不影响意思的『的、了』」这一口径报告。平均是按讲次简单平均还是按字数加权：原始报告已删除。术语核对（上表最后一列）后来单独再测时，实际 **0 处替换**，分数与 r3 相同，未接入 App。

8. **第五轮 B 阶段定向训练**  
   原计划针对五欲、根机、不堕两边及漏字多的段落再训练。数据准备开始后，因担心继续用会省略口语的听打稿训练会加重漏字，B 阶段停下，改为下面的计划一。B 阶段若后来产生过完整分数：原始报告已删除（对话中未见跑完报告）。

9. **计划一：用原版模型补标后再训练 1 个 epoch（失败，未采用）**  
   用未微调的底模重识别约 103 小时训练段落，把底模听到而听打稿没有的固定口语词补进标签，再训 1 轮。规则写错：词表含「啊、呀、呢、吧、嘛」，且没有按句首 / 句尾区分，结果标签里插入了 37,945 个「啊」和 7,487 个「呢」。候选分数低于 r3，未替换：

   | 讲次 | r3 严格 / 调整 | 计划一 严格 / 调整 |
   | --- | ---: | ---: |
   | 佛教徒的生活模式 | 92.01% / 97.52% | 87.61% / 95.73% |
   | 语加持 | 95.54% / 97.35% | 88.50% / 94.04% |
   | 四谛下 | 93.86% / 97.06% | 87.08% / 93.34% |
   | 介绍慧灯禅修 | 91.00% / 97.39% | 83.41% / 90.87% |

   其余三讲比 r3 低 3 到 7 分。底模识别缓存已删。当时建议修正规则后再跑（只补连接词和句中「的、了」，不补「啊、呀、呢」）；这一次重跑的计划名称、是否执行及分数：原始报告已删除。对话与笔记中找不到名为「计划 5c / Plan 5c」的完整结果，该条只能标「原始报告已删除」。

10. **本机大模型对比（留出讲严格分，当时 r3 为 92.01%）**  
    FireRed2-AED：75.99%（beam 3），多插 2464 字；五欲 0/7，出离心 0/10。beam 5：76.07%。  
    MiMo-V2.5 8-bit：77.90%，漏 18、多插 2468。两个对照讲「都只有七成多」，精确分：原始报告已删除。

## 4. 计分规则

两套主要口径：

1. **严格分**  
   对照人工听打稿，按 `scripts/eval_accuracy.py` / `eval_segments.py` 的去标点规则算逐字一致率。听打稿里省略、但录音里确实说过的口语（如「是、这个、这样子」），会记成模型多写，因而严格分偏低。第 1 至 4 轮和第五轮 A 阶段当时公布的，都是这一口径。

2. **调整分（真逐字调整）**  
   准确率按「讲者实际说出来的话」来看，而不是要求模型去迁就听打稿的省略。后来明确的规则包括：  
   - 句尾语气词（紧挨标点的「了、的、呀、呢、吧、嘛、啊」）漏掉不算错。  
   - 不影响意思的句中「的、了」（例如「我的心」→「我心」、「修完了以后」→「修完以后」）漏掉不算错。  
   - 句首或句中的「这个、那个、就是、然后」等若漏掉，**仍然算错**。  
   - 保留讲者口语，只去掉「嗯、啊、呃」这类语气词；不要求稿子写成书面语。  
   第一次公布「真逐字」97.23% 时，还用过一条辅助规则：r3 多写的字，必须另外两个模型在同一位置也听到，才改判为正确；佛教术语错误不放过。异体字 / 简繁 / 「叫作、叫做」可另报一列归一分数，应用里只做了保守统一，不把「作 / 做、坐 / 座」或真实术语错误（如「不堕两边」「五欲」）全局替换掉。

因此：**不能把底模的 76.41% 严格分直接和当前的 97.44% 调整分当成同一套尺上的提升。** 同一留出讲、同一 r3 权重，在只改解码之后，严格分是 92.05%，调整分是 97.56%。从 76.41% 到 88.02% 才是同一严格口径下、由微调带来的提升；从 88.02% 到 92.05% 主要来自解码参数和补字规则；97% 一带的数字还包含计分口径的调整。

原始调整分脚本在已删除的 `~/ASR/bench_large` 里，当时没有提交进仓库。对话中曾计划把它重写成 `scripts/eval_adjusted.py`，截至本记录写入时，仓库里还没有这个文件。

## 6. 错误分析

第四轮在「佛教徒的生活模式」上，对当时 r3（严格分 88.02%）的 1433 个错字分类如下（百分比为四舍五入后的公布值；笔记里还有一位小数的写法：漏词 38.3%、插入 / 重复 25.0%、声学误识别 17.5%、口语 / 书面参考差异 12.2%、同音 / 术语 6.5%）：

| 类别 | 字数 | 占比 |
| --- | ---: | ---: |
| 漏字 | 549 | 约 38% |
| 多出来的字或重复 | 358 | 约 25% |
| 真正听错 | 250 | 17.5% |
| 听打稿改成书面语、与原话不同 | 175 | 约 12% |
| 同音字和术语错误 | 93 | 6.5% |
| 数字、格式和简繁异体字 | 8 | — |
| 合计 | 1433 | 100% |

漏字与重复合计约占 **63%**。扣掉「听打稿改写」和异体字后，校正准确率约 89.50%。

改用 rp1_tok1 之后，留出讲漏字从 633 降到 212，多字从 546 升到 595。之后按调整规则看，四讲里最大的一块曾统计为漏掉的实词 618 字，其次是佛教术语 111 字。第七轮认为剩下的错大部分仍是漏字，多半出在很长的段、语速特别快或特别慢的段，以及切段接缝；补字规则只把留出讲漏字从 212 降到 206，四讲调整平均只提高 0.02 分。

有一种「剩余错误里约 82% 是漏词」的说法，在现有对话和工作笔记里找不到对应出处，标为 **原始报告已删除**，不以 82% 作为可引用数字。

「上一段当提示」不能用：只给上一段时，模型会把上一段抄进来，分数掉到 43%。加上词表后，留出讲只提高 0.22 个百分点，四谛下反而下降，未接入 App。
